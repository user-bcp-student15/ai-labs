# HU-01 - Validación segura del token entre API y auth

## Origen
- `H-API-01` (componente `api`), estado **Pendiente**; bloqueado hasta coordinar con auth el formato del token.
- Evidencia: `api/app/main.py:14`, `api/app/main.py:19-24` y `api/tests/test_api.py:11`.

## Contexto
- La API acepta un token codificado en Base64 que no está firmado y cuya validación depende de un secreto embebido. Según el hallazgo, esto permite fabricar identidades y roles; tampoco se verifica emisor ni audiencia.
- El formato debe coordinarse con auth, cuyo flujo no fue revisado como parte del hallazgo.

## Ajustes necesarios
- Acordar con auth un formato de token firmado y compatible con ambos componentes; no fijar aquí una biblioteca o algoritmo.
- Verificar en la API la firma y los datos de emisor y audiencia acordados.
- Retirar el secreto embebido y proporcionar el material de verificación mediante configuración, sin registrar secretos ni tokens.

## Criterios de aceptación
- Una prueba de integración confirma que la API acepta un token válido emitido por auth y conserva la identidad esperada.
- Una prueba confirma que modificar el contenido de un token emitido invalida la firma y que la API responde `401`.
- Una prueba confirma que un token fabricado sin firma válida no permite elegir una identidad o rol y que la API responde `401`.
- Pruebas con emisor o audiencia distintos de los acordados son rechazadas con `401`.
- La configuración de firma/verificación no contiene un secreto embebido en el código ni se registran secretos o tokens en las pruebas ejecutadas.

## Evidencia esperada
- Pruebas de integración API-auth para token válido, contenido alterado, token fabricado y emisor/audiencia no válidos, con sus resultados.
- Evidencia de configuración que muestre que el secreto no está embebido, sin exponer su valor.
- Resultado de revisión de logs que confirme que no contienen tokens ni secretos.
